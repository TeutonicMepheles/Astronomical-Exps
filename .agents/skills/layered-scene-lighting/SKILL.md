# 二维场景资产与独立调光

目标：关闭所有光源后，场景仍保留自然的环境光、材质、玻璃反射和空间层次；打开光源时，在固定几何上增加灯光。避免由亮图局部压暗造成的焦黑窗框、光晕暗斑和残留染色。

## 工作范围与入口

- 先遵守根 README、`docs/AGENT_GIT_WORKFLOW.md` 及负责实验的 AGENTS、REQUIREMENTS。本 skill 不扩大目录权限，不代替贡献者协作流程。
- 制作资产或独立美术预览，不等于授权接入正式实验、提交、推送或发布。保持原有工作和已交付版本。
- 光污染实现、资源接入或跑测前，读 `experiments/light-pollution/tools/audit/AGENTS.md`；记录解码、纹理、整景合成、事件和释放的适用风险。仅仓库外资产处理可说明正式页面跑测不适用。
- 本流程沿用用户确认的 **Seedream 5.5、原生 2K**；用户本轮指定优先。生成前检查实际模型 schema。LibTV 操作通过 `libtv` CLI，按可用的 `libtv-cli` skill 与 CLI 帮助执行；不自造 HTTP 调用或静默换模型。工具不可用时说明限制，仍可整理已有资产与配准信息。
- 制作提示词、计算灯光或核对既有案例时，按需读 [制作与验证细节](references/production.md)。
- 涉及灯罩、墙灯、车流或移动眩光时，读 [参数光与动态层](references/runtime-lights.md)。整景静态光增量只能调强度，不能假定它支持改变配光方向或移动光源。

## 参考图与对象提取

1. 先查看原图，识别可独立控制的对象和遮挡关系。为每个近景主体做紧裁切，使它在输入中占据绝对主体位置，保留少量完整轮廓余量。
2. 对象提取节点只连接该对象的局部参考或已有独立资产。需要暗态色彩参考时，也连接同对象的局部图。不要把整张城市图交给每个对象，再用长描述要求模型重新设计镜头。
3. 提取时保留原有观察方向、消失点、屋顶边线、可见立面比例和材质。只对被遮挡部分做必要补全。拒绝改变灯头、增添建筑、背景地面残留或虚构店铺等结果。
4. 核心单体独立提取；远景建筑群可作为一个整层，保留楼间相对位置、尺寸与间距，统一亮暗，不为其额外拆单楼。
5. 原生 2K 指生成输出。小裁切放大上传不代表恢复真实细节；保留原始像素尺寸。不要把多对象图集切成低分辨率小图后声称每个对象均为 2K。

保存原图、裁切坐标、输入节点、提示词、模型参数、回执和原始输出。重试先查询原节点状态；已成功的任务只重试下载。单次只读查询或下载连接失败最多再试两次，仍失败则保留任务标识并报告；提交结果不明时先查状态，不重复提交。生成失败或质量不合格先定位原因，有具体修正且仍在用户授权内时再生成；相同原因再次失败就停止该项，报告缺项，不无限重复付费生成。

## 先制作干净关灯底图

- 从独立对象制作真实的无人工照明外观：窗户、屏幕关闭，移除已烘焙的暖光、紫蓝反光、墙面染色和光晕，保留深蓝灰环境照明、材质与立面明暗。
- 关灯玻璃保留微弱环境反射；窗框、屋檐和建筑轮廓保持正常材质。不要把玻璃做成死黑洞，不对窗框描黑或涂黑。
- **不得用“亮图 × 反向光遮罩”生成正式暗态**，也不要在整景里另乘 RGB 系数掩盖不合格暗底。调光只改变增加的光，不压暗固定底图。
- 生成暗底可能轻微移动几何。检查轮廓与立面特征，必要时做平移配准并复核；外轮廓对齐不代表所有窗框已对齐。明显的透视或窗位变化应返工，不用变形强行吞掉。
- 锁定一份权威画布、alpha、锚点与几何映射，所有状态和通道共用。alpha 边缘缺少有效 RGB 时可做邻近材质延展，避免缩放采样黑边；不能靠扩大黑色轮廓补洞。

## 按控制对象分灯光通道

先列控制矩阵，再制作通道。例如商业体的窗灯与广告屏分开；远景群组仍共用一个总控制。用户要求全部窗户亮灯时，逐个可见立面、底层玻璃门和阁楼窗核对，不只点亮原本已有亮色的窗户。

每条通道可包含以下独立层，或在无需分别控制时合并为一个光增量纹理：

| 内容 | 制作要点 |
| --- | --- |
| 窗户、灯头、屏幕发光 | 按玻璃或发光开口边界定位，保留窗框和分隔条；屏幕白色高光、紫色部分也要覆盖 |
| 墙面、地面受光 | 按接收表面限定范围，结合距离平滑衰减，避开屋檐、转角、遮挡及其他独立光源 |
| 外溢光与光晕 | 独立透明层或光增量，柔和消失；该通道归零时完整消失 |

颜色阈值可辅助定位，不能代替几何核对。不同控制对象的发光与受光不能不可逆地烘焙在一起。远景也需要干净暗底与有层次的受光，不能把整层固定灰度压暗当成自然关灯。

## 合成与调节

- 在**线性颜色空间**增加光：`显示色 = encode(暗底线性色 + Σ 强度 × 对应线性光增量)`。零强度严格回到同一暗底。
- 光增量可在已配准的发光区域提取正差值，并补独立受光；不能直接对两张独立生成图做整图差分，避免几何差、纹理差变成光边。
- 明确纹理编码和混合约定：sRGB 编码的线性光增量先解码再相加；普通 RGBA 光晕按其约定叠加。避免重复 gamma 转换、重复 alpha 乘算或把增量贴图当普通底色覆盖。
- 冷暖调节同时影响该光源及其受光，不能重染建筑底材。强度范围和冷暖先作为视觉演示；不擅自标定真实光强、开尔文、星数或波特尔等级。
- 画布、alpha、锚点及场景变换保持固定。场景合成时对本体和所有光层应用同一变换，包含外溢余量；前景遮挡再覆盖，避免建筑漂浮和前排灯杆被看台吞掉。
- 第一轮可只选一个核心对象，在特写和原场景中证明暗态、独立调光与受光效果，再推广。不要声称一个对象的小样等于全景已换用新流程。

## 预览与验收

提供简洁的关灯/点亮、独立通道滑块、必要的冷暖与特写/场景切换。修复旧暗态时提供旧版对照。按项目约定保持 16:9，无需悬停、滚轮或页面滚动，保留可访问标签。

交付前核对：

- 美术：全暗无焦黑框、暗斑、残余发光染色；各立面材质和玻璃仍自然。检查单开窗灯、单开屏幕、全亮和中间强度；放回场景核对位置与遮挡。
- 几何：所有层原生尺寸一致，窗口与屏幕边界配准，切换不移动。自动像素检查不能替代透视与美术查看。
- 独立性：改变窗灯不点亮屏幕；改变屏幕不点亮窗户。零强度下改变该通道冷暖，暗底像素应保持不变。
- 渲染：验证多个强度档、反复开关、两种视图、离线打开及渲染错误。区分实际 WebGL 检查与仅截图生成成功。
- 性能：静止不新增重绘循环；计算当前加载纹理的 RGBA 开销，检查事件合并、缓存与释放。短时桌面检查不代表白板、低端设备或长期验收。

保存可复现的源图、通道、摆放清单、预览入口和验证报告，清楚报告哪些对象已更新、哪些沿用旧版，以及尚未接入的功能。源码交付执行根流程要求的检查；不为通过测试削弱断言。

资产包可提供显式 `bundle-manifest.json`，用 `python .agents/skills/layered-scene-lighting/scripts/validate_bundle.py <manifest>` 校验。该工具检查真实图片、2K 画布、通道引用、透明底与包内路径，不证明透视、美术、光度学或动态功能正确。契约见制作细节。
