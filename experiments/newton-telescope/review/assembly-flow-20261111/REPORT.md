# 拼装后自动检视修复 · 2026-11-11

## 原因与改动

自动完成反馈、500 ms 延迟、12 秒匀速一圈、隐藏控制坞、右下金色参数观测入口和弹窗新文案已存在于本工作树的未提交修改中。旧入口仍直接 requestAssembly，且自动流程用 developer.enabled 排除了开发者预览，因此上一轮开发者跳转试玩未进入自动检视。

本轮移除开发者模式对实际拼装完成事件的排除；本体点击改为重新自动检视。查看器启动失败不再冒充已完成一圈。自动一圈期间键盘也不能改变方位，避免人工输入破坏匀速；完成弹窗获得原生模态焦点时不再被查看器拉回。

保留已有音效、反馈、500 ms 延迟、扫描转场、12 秒一周、按钮和弹窗文案。旧需求已标记被自动检视流程替代。仅修改本实验。

## 验证

- npm run check：通过，0 errors。
- npm test：通过，23 个工程测试及光学/课程检查。
- npm run test:browser：失败于 previews/components/progress.test.cjs:12 的已有进度断言，未修改公共预览或降低断言。
- nightly-assembly.browser.cjs：通过；实际拖拽、音效调用、UI 反馈、508.8 ms 延迟、自动一周后弹窗、继续观察留在 3D、进入第三阶段、控制坞隐藏、右下 CTA、开发者模式自动流程、重新打开和中途退出清理均覆盖。证据见 assembly-regression.json 与 PNG。
- Chrome 实际点击：开发者跳转组装后完成两面镜片，自动打开 3D，完成后弹窗，“继续观察”留在 3D；右下金色参数观测按钮可见。
- 离线 file:// 完整拼装专项：通过，自动打开延迟 507.8 ms，含开发者模式和再次进入；见 offline/assembly-regression.json。
- npm run export -- newton-telescope：通过。资源查询版本号不兼容当前离线导出器，已撤回该临时方案；旧浏览器标签需要强制刷新加载当前脚本/样式。

## 性能专项检查

适用项：自动动画时钟、WebGL 重绘、转场与重复开关、资源生命周期。沿用查看器现有 rAF，未添加第二条渲染循环。专项断言确认旋转一周后停止 auto，400 ms 内新增绘制不超过一帧；中途返回销毁查看器，取消回调，重新打开可运行。隐藏页继续沿用 visibilitychange 暂停，不累计后台时间。未进行新旧版本 GPU 帧耗时对照，未完成白板触控、低端设备和长时间运行验收。音效验证确认 Web Audio 调用，未宣称人工听音验收。
