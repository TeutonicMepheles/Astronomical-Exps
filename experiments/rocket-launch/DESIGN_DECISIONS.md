# 火箭发射：交互编排与原型决策

## 需求来源及边界
依据 2026-11-11 用户指令及两份附件 REQUIREMENTS.md、火箭发射实验-页面功能规格.md。甲方 demo 仅用于核对功能，不参考视觉、交互或源码。原有箭体自重输入保留，不能因新规格只列推力与载荷而删去。页面只修改 rocket-launch 目录，不改变其他实验。

## 信息优先级与任务路线
全局只保留三章导航、章内步骤、返回/下一步。章节不强制解锁，教师可直接演示；主按钮始终只有一个首要动作。章内前后切换保存实验状态，局部重播不清历史。

## 布局与操作
1600×900 逻辑舞台等比缩放，4:3 留边而不是裁切。中央主场景占最大面积，左侧是当前任务操作，右侧仅在需要时呈现固定说明或记录。全屏无滚动，关键操作不依赖 hover。说明文字只解释当前观察，不堆叠指导小字；操作过程以高亮、轨迹增长、部件吸附、记录飞入抽屉传达因果。触屏 Pointer Events 与键盘替代操作并行；组装可用“选部件→选槽”作为拖动辅助，但不能替代真实拖动。

## 科学与数据决策
- 推力挑战为定性教学示意，档位无伪造真实单位；自重和载荷相加决定质量负担，低于重力不能起飞。示意距离及高度明确标注，不暗示工程预测精度。
- 宇宙速度含低速 4.5、第一 7.9、第二 11.2、第三 16.7 km/s，前三者地心对照保持同一比例尺。第一为近地圆轨道，第二为理想地球逃逸门槛。
- 第三 16.7 km/s 是从地球出发、利用地球公转且方向合适时逃离太阳系的近似条件，不应直接画成“更大的地心椭圆”。太阳参照示意单独标识，不能与地心统一比例尺混称。
- 分离减少后续需要加速的质量，不用瞬时速度跳增表现。阶段推进与部件分离动画对应。
- 本机 localStorage 持久化挑战记录，内存作异常回退，不实现跨设备同步；返回/重播不丢记录。说明文档披露该选择。

## 复用与资产
复用 shared/components/globe-shader-renderer 公开 API；地球四张配套贴图复制到本实验 assets 并登记来源，禁止跨实验私有运行依赖。牛顿望远镜光轴逻辑先检查是否通过 optical-beam 公共接口可用，气球串线仅复用这一空间约束思路，不复制私有实现。手绘箭头和颗粒贴图可复制登记；整箭、透视、组装、分级共用一套同坐标透明底拆件。VD 源图火箭高 700px、最大芯宽 220px、单侧助推器 70px，舞台缩放约 560px 高。

## 性能适用项
单一 requestAnimationFrame 驱动当前步骤；离开步骤取消动画、隐藏页面暂停；静态界面不持续重绘。限制 canvas DPR、缓存纹理、复用几何和解码后的图片；不对每帧分配大量对象或更新完整 DOM。减少动效偏好下缩短过渡，但保留轨迹与结果可读性。测试包括多视口无滚动、错误日志、完整流程、记录保留和离线依赖。

## 明早建议重点体验的三处方案

### 1. 气球：直接操作比“参数后点播放”更适合起步
已把主操作从左侧菜单搬到场景内的打气筒：按住持续充气、松开立即飞出；左侧仅留慢动作与重新开始。右侧可拖动导向线方向，观察运动与喷气保持相反。借鉴牛顿望远镜“可操作轴线约束动态表现”的思路，而非复用不适用的光学求解器。现成 optical-beam 依赖 Three.js，是光晕渲染层，不为二维气球专门引入这一重依赖。
- 取舍：放弃“先选充气档位再发射”的间接方式；它更容易控制比较，但把充气过程割裂成按钮。
- 待讨论：拖轴是课堂的有用探索还是额外干扰？可以保留为教师工具，学生首轮只按住与松开。
- 美术边界：气球三态和打气筒已接入；三帧过渡仍为切换，尚未做连续形变。气流为示意，不是流体仿真。

### 2. 宇宙速度：单档聚焦 / 同尺度叠轨可以现场切换
默认一个固定速度一个结果，避免初学者同时追四条线；“叠加轨迹对照”提供第二种参考方案，前三档在同一地心比例尺重叠，便于老师讲门槛差异。第三档单独换成太阳参照示意，不用一条更大的地心曲线冒充太阳逃逸。
- 取舍：不做连续拖动速度，保留清晰的四张固定速度门票；不让数值滑动取代对物理门槛的理解。
- 待讨论：地心叠轨比左右分屏更省认知转换，但重叠时路径分辨仍需优化；当前配色仅是原型。可用真实课堂任务比较两种阅读方式再定稿。
- 科学边界：地心轨道以圆锥曲线作定性演示，发射点为放大的高山位置；7.9/11.2 是近地理想参考值，不代表图示高山的精确轨道解。第三档只示意参照关系，不声称数值积分复现太阳系逃逸。

### 3. 组装：逐段引导 / 自由装配是两种可体验方案
默认下一段散件与目标槽同时亮起；允许直接切“自由装配”，取消提示但不改变部件或完成条件。两方案共用七类拆件，目标区按空间顺序由整流罩、卫星、上级、级间段、下级到发动机，助推器置于侧边。拖错退回，缺件检验明确指出缺项，成功后点火。
- 取舍：当前采用可读的装配板，不把细小美术轮廓直接当命中范围；对智慧白板更稳，也让“接下来做什么”通过双端高亮而不是长说明表达。
- 待讨论：装配板是清晰但偏教具化的方案；后续值得比较“直接在整箭轮廓上吸附”，那版会更具空间感，但遮挡与误触需要重新设计。当前不是最终手感。
- 资产复用：组装、结构透视、分级共用同套插图；透视是教学插图，不标精密工程位置。分离先移动下级、级间段与助推器，再移整流罩，上级继续飞行。

### 16.7 附注的字色是怎么定的（以及一条方法论）

**结论**：`rgba(169,176,191,0.88)`。按 WCAG 定义（声明色合成到实测底色）是 **5.82:1**，底色在行带内波动时落在 **5.57–6.05**；小字下限 4.5 之上，层级用相对判据（附注 ≤ 小窗标题 − 1.0）也满足。

**过程值得记下来**，因为前两把尺子都错了：
- 先用像素分位（框内 ≥p97 的像素取中位色）。校准图上覆盖率 19%→100% 的五个色块**全报 7.10**——它只取最亮 3%，量到的其实是"这块裁剪里实心像素够不够多"，不是这行字好不好读。
- 再换框内均值，同样不成立：12.5 px 的笔画只占框面积约 53%，均值把字缝当背景积分，同一行字报 1.89。
- 最后回到定义：对比度有 WCAG 定义，**声明色 + 底色，两个输入一个输出**，不需要截图、不需要 dpr、不需要裁框、不需要分位。三方独立复算落在 5.78 / 5.82 / 5.82。

**原则**：有定义的量就直接按定义算；要靠校准图才能立住的代理量，只配用在没有定义的场合。

**一处别记账记错**：玩家看到的"偏淡"是真的，但那是 12.5 px 的**笔画密度**（字体/字重），不是对比度——颜色达标与观感偏淡可以同时成立。

## 复核口径（给复核者，不是设计决策）

这几条是本轮反复踩出来的，改版面或量像素之前先读：

- **px 有两种，别混**：本文所有 px 都是**逻辑画布 px**（backing 1100×650）；屏幕 CSS px = 逻辑 × k + 横向留白。**k 不是常数**，它随视口高变（1600×900 下 0.989231、1280×720 下 0.791385、1920×1080 下 1.187077），最稳的取法是直接量 `canvasRect.h / 650`，别回推。`canvas{object-fit:contain}` 让缩放等比（kx = ky），所以画面上的圆是真圆。
- **不要加 `.stage{aspect-ratio}`**：宽高比差的那部分现在是左右留白（1600×900 下各 31.9 px），加 aspect-ratio 会把留白挤掉，所有既有的"逻辑 px → 屏幕 px"换算一起错位。
- **弧长有两个名字**：**角扫**（度）与**真弧**（沿路径积分）。4.5 档是角扫 15.93°／角扫×R 0.278 R／**真弧 0.307 R ≈ 55.1 逻辑 px**（系数 1.102）。引用时必须写是哪一个，否则同一个弧会出现 39/42.9、95.5/98.1 两套数。
- **闭合查缝、不查跨度**：闭合档要逐 0.5° 分箱数缺口；只看总跨度会把"范围被裁"（曾把圈底切掉 37°）和"亮度被压"（taper 压暗约 8.5°）读成同一个数，从而漏掉真缺陷。
- **报像素数必须带阈值**：同一个闭合圈的最低行，严阈值（只吃实体描边）506、中阈值 514、宽阈值（含 10 px glow 尾巴）521——三个都对，不带阈值就成了三个互相矛盾的结论。

## 修订（2026-11-11 夜，第二轮）：宇宙速度这一章按规格与裁决重做

上面「2. 宇宙速度」里的取舍是在甲方批评之前定的，其中「不叠加、不连续」的说法与本轮实现已经不一致。本轮定稿如下，**以本节为准**。

### 结构：档位是控件，连续感由背景谱承担
- 规格 3.2-1 原文「固定速度档位，不做无级拖动」不动。四个档位就是控件：点到即停，沿尺拖动也只会在档位间跳，不存在档位之间的中间值。
- 速度仍然是「量」而不是「标签」：这一章的关键画面是 **26 条同族轨迹组成的背景谱**，四个档位是谱上被点名的取样点，当前档位那一条点亮成暖色。学生看到的是「同一条曲线在不同初速下变成什么」，不是一个按钮换一张图。
- 谱的取样按 u=(v/7.9)² 等距（u = 0.300 + 0.164 i，26 条），刻度也按 u 落位：4.5 / 7.9 / 11.2 / 16.7 = 0% / 16.3% / 40.7% / 100%。**不另画按速度等距的尺**——两根尺同屏，必有一根在骗人。

### 一句话必须写进交付的尺度声明
**图中以发射高度的环绕速度为 7.9 km/s 归一，尺度为示意。** 炮口在 0.08 R 的低塔上（水平发射，发射点即远地点），因此：7.9 是精确圆（e = 0，不是「几乎正圆」）；逃逸门槛 = 7.9√2 = 11.172，正好落在 u = 2；4.5 的落回弧扫过 15.93°（角扫×R = 0.278 R，**真弧 0.307 R**，按 s≈179.63 px/R 是 55.1 px）；7.9 的圈离球缘 0.08 R，不会被球缘吃掉。
界面档位写教材值 **11.2**，它是门槛 11.172 的取整（+0.25%），所以这一档的轨迹略微开口——**不是恰好逃逸**，也不能反过来说「11.2 就是精确逃逸门槛」。

### 第三宇宙速度：换参照系，不切页
16.7 不弹按钮、不切页签：地心层淡出，同一块画布上接管的是日心小窗——**独立画框 +「换个参照系：太阳」+「不与主图同尺 · 示意」**，窗内保留速度预算条（地球公转 29.8 + 逃出地球余速 12.4 = 42.2，对着太阳系门槛 42.1），让 16.7 这个数有来历。低档位不显示这个窗：在日心尺度上，贴着地球飞的几条根本看不出差别，挂一块空窗是假承诺。

### 第一章与第三章同步改的两处
- 第一章：打气筒本体就是控件（按住压缩、松开弹回），画面上只留一个大百分比，取消文字按钮。
- 第三章：质量是一根肉眼可见变短的条（每分离一次短一截），右侧给当前占比；分离位置按整体质量比例 0.72 / 0.10 / 0.18 分布，装配用「散件托盘 + 整箭幽灵轮廓装配轴 + 槽位虚线」。

### 可机器核对的实现口径
`window.RocketModel` 暴露：`model(v)`（u、e、a、peri/apo、kind）、`pathOf(v)`（采样点、闭合残差、末端半径）、`uOf`、`r0`(=1.08)、`vCircKm`(=7.9)、`vEscKm`(=11.172)、`gears`、`spectrum`/`spectrumU`（26 条谱的 v 与 u）、`cam()`、`toPixel(x,y)`（物理量→画布 px）。轨迹与刻度一律由它算出，渲染再画；测试 `test-velocity.cjs` 从这些数反算 e=|u−1|、两处质变、7.9 的 e=0、11.2 的 u=2.0099、刻度 0/16.3/40.7/100% 与谱的 e 指纹（最小两个 0.044 / 0.120，最大 3.400）。

### 仍未做到（诚实清单，更新）
- 第一章气球三态之间仍是切换，没有连续形变插值。
- 装配仍用矩形槽位，真正的整箭轮廓吸附留作下一轮。
- **闭合圈的缺口有两个、成因不同，修法互不替代**：底部约 **37°** 是**范围**被场景裁剪切掉（`velocity.js` 的 `ctx.rect(0,0,W,500)`，环底 510 > 裁线 500；已改成 `RAIL.y−70 = 530`，给 glow 留 10 px 余量）；炮口一侧约 **8.5°** 是**亮度**被 `taper` 压暗（首尾各 14% 压到 0.62–1.0，范围没变，学生仍看得见连贯的圈）。前者已修，后者留到下一轮：`closed` 分支传 `taper: false`。不要把两者写成一条——改裁剪切线修不了炮口，关掉 taper 也修不了底部。
- 相机随档位后退的速度曲线是手感调的，没做视觉舒适度实验。
- 推力、比冲、载荷的真实数值仍是待确认项；质量条三段比例是示意，不是工程配比。

### 补三处规格差距（Cindy 17:13Z 对着 §3.2 逐条给的）
1. **结果说明**：规格 §3.2 要求「当前速度、宇宙速度名称、轨迹和**结果说明**」四件同时在。现在每个档位在状态词下面只有一行说明，四句各不相同（4.5「不够快：升到最高点就被地球拉回来」/ 7.9「正好够：不掉下来，也不飞走」/ 11.2「过关：越过这个门槛就不再回来」/ 16.7「再加上地球自己的 29.8，才够离开太阳」）。一行，不做段落——老板明确反对用副文本堆解释。
2. **本章的重播**：规格 §3.2-3 要「重播和对比」。对比由常驻的 26 条谱承担；重播做成**再按一次当前档位 = 沿已画好的曲线跑一颗光点**（0.9 s）。没有做「描线」动画，原因是验收侧要从渲染像素拟合整条圆锥曲线，描线中的半条曲线会让拟合点变少、σ 变大——重播必须是「看得见，但不改变可测的那条线」。
3. **统一比例尺**：规格 §3.2-3。三个地心档（4.5 / 7.9 / 11.2）现在共用一个取景 `s = (SCENE.h − 84)/(2·R0) ≈ 179.6 px/R` 与同一个球心，切档时球不缩放、球心不漂（实测三档 `cam()` 逐位相同）。16.7 换参照系，另算。

### 球面颗粒用的是程序化噪声，不是纸纹贴图（写清楚，免得被当成贴图在跑）
`shared/components/globe-shader-renderer` 的 `grainMode` 默认 0、全树没有任何地方给它赋非零值，mode 0 走程序化 `fbm3`——**纸纹贴图从未生效**，这一点 Assets 与 Cindy 各自独立核过。选择保留程序化的理由是与仓库里其他实验同族（它们都是 mode 0），而不是"用了 `grain-tex-512.png`"。原先传给渲染器的 `grainUrl`/`grainBrushUrl` 两个参数因此是死参数，已删除；连带 `grain-tex-512.png`、`grain-brush-512.png`、`grain-ref-512.png` 三个未被引用的贴图也从实验目录里删掉（恢复路径见下）。

页面级那层颗粒（`assets/grain-256.png`）是**单向亮尘**：单张全白砖以 `source-over` 叠上去，`globalAlpha` 0.18、alpha 均值 0.263，**等效不透明度 4.7%**。在深底上它的主要效果是**均匀提亮**——`Δ = 0.0474×(255−base)`，base=30 时约 **+10.7 灰阶**；颗粒本身的起伏只有 `0.18×0.1526×(255−base)` ≈ **±6.2 灰阶**。**它与参考一不同**：参考一是零均值加法颗粒（±7 对称、|p5|/p95 = 1.00），振幅与本页同档，但**负的那一半在这里被换成了平底**。复现需要白/黑成对叠（白 `plus-lighter`、黑 `multiply`），本轮没做，是取舍不是已完成项。

**恢复路径**：要切贴图颗粒须全仓一起切（其它实验也都是 mode 0）。母版在仓库历史里：`git show bc15a51:experiments/rocket-launch/assets/grain-tex-512.png`（512²、RGBA、R=G=B=A、均值 .500、σ .040，sha256 `7dc6b89a5fc71bdba93a3517f62db0a32cdcb347f0d4fac696180b5d83b1e351`）。这段是自足的，不指向仓库外的任何文件。**唯一硬约束是 R=G=B=A**：L 8bpp 或 RGB 分离的贴图接进 `u_grain` 会静默失效、不报错。
