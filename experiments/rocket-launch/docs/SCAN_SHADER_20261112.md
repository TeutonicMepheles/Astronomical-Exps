# 透视与装配的网格扫描轮廓

根据用户新要求，结构透视不再只留下内部零件。外壳、整流罩和四助推器用半透明网格扫描线 Shader 保留完整轮廓；装配时用同一模型的网格参照表示安装位置，散件保留实体。装入一个模块后对应参照消失，退回恢复；点火和分离不显示参照。

## 实现

- `scan-material.js`：基于模型坐标的米制网格、细扫描线、边缘亮度；fwidth 抗锯齿，透明材质不写深度，采用正面绘制。静态扫描纹理不新增 RAF 或时间推进。
- `rocket-3d.js`：27 个扫描外壳代理复用原几何；装配参照复用同一 GLB 的几何及完整装配变换。实际散件和参照分开管理，没有重新建模或修改原始资产。内部实体优先 raycast，扫描轮廓可作为模块选择的后备；选中时克隆材质变为暖色，退出后恢复并释放。
- `test-scan-shader.cjs`：真实 GPU 像素、穿过网格点选六个内部部件、点选扫描外壳与隔离高亮、外观恢复、安装/退回参照、20 次往返及分离隐藏回归。
- `test-3d.cjs`：资产计数排除运行时扫描代理；透视断言改为验证真实 Shader 轮廓和内部可见性，保留原有装配、分离、暂停、取消、失败、释放与前两章回归。支持本轮独立证据目录，保留上一轮结果。

已运行：

## 性能专项检查

适用风险为透明叠层和额外 draw calls、Shader 编译、选择材质克隆、参照生命周期。几何共享，不增加纹理或几何缓冲；静态时仍按需渲染。20 次往返几何数量稳定；主专项 destroy 后几何为 0、事件已取消，分离中没有参照。

另在有窗口 Chrome、1600×900、DPR 约 1、RTX 5080 下串行运行 `test-3d-performance.cjs`，结果保存为本轮 performance-chrome.json：14.161 秒、1060 帧、rAF P95 13.4ms、P99 13.5ms、0 长任务、0 脚本错误。上一轮同流程 14.128 秒、1058 帧、P95/P99 同为 13.4/13.5ms；仅是相近短样本，不据此声称性能提升。首次有窗口整流程采样在等待关卡时超时，未取得失败帧，原因未归因；追加独立 8 秒时钟诊断（chrome-clock-diagnostic.json）正常推进到等待状态，随后整流程重跑通过。短测不能证明低端 GPU 或长期内存稳定性；实体白板、远距阅读和最终视觉接受仍待验收。
