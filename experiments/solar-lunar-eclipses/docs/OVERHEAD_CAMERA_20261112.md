# 原观测截图与垂直黄道面视角

本轮依据用户两个明确要求：提供恢复原视角后的日食/月食整页截图；在总览中新增垂直黄道面的可选视角，保留已有斜视、平视和观测布局。

## 截图

`capture-shadow-review.cjs` 在 1600×900、DPR=1 下拍摄原观测视角，包含日食和月食各五张：本影刚接触、食甚、本影离开前、半影刚接触、半影离开前。

接触角来自前轮的整个球面接触点，而非观察点 A 的食相节点。刚接触取理论接触后 0.02°，离开前取理论脱离前 0.02°；精确相切时交线可退化成不可见点，不用一个虚构圆环代替。截图未裁切、未修图。这里提供实际画面供检查，没有把它们自动判为影锥视觉验收通过。

整页截图集（本地评审证据，不随工程发布），原图及参数见 [capture.json](shadow-review-20261112/capture.json)。

## 新视角

- 总览左上角新增“垂直黄道面”按钮，原“平视黄道面”按钮保留。两个按钮分别可返回原斜视，可直接在平视与垂直视角之间切换。
- 垂直视角看向黄道面法线：elevation=π/2，黄道面中的两条正交单位轴等长投影、深度均为 0，黄道面法线投影到屏幕中心方向。因此黄道面圆轨道显示为圆，不是较高角度的斜视。
- 新视角单独将总览显示尺度设为 .38、太阳显示中心 y=400，使完整地球公转轨道、月球轨道和标签留在画幅内；这些取景参数只在 `view=overview && camera=overhead` 时生效，不改变科学参数、时间或月相。
- 原斜视和平视的所有显示值沿用原值；日食/月食观测仍用 yaw=.75、elevation=.16、原地球中心和 148×zoom 半径。进入观测时忽略总览的垂直选项，返回总览后保留用户选择。
- 未修改本影、半影模块或原观测布局。视角控件在观测中隐藏，不增加悬停或滚动操作。

## 检查

- `test-overhead-camera.cjs`：法线方向与圆投影断言、时间/月相不变、原视角往返、原平视保留、两种总览入口进入观测时的几何全等、继续播放、1024×768 和 1920×1080 无页面滚动均通过。
- 同页两种入口的观测整页图只有 RGBA8 合成量化级别的差异：29 个通道、最大差值 1/255，天体中心、半径、姿态、时间与月相逐项完全相同。没有把 PNG 字节哈希当作跨浏览器进程的视觉一致性判据，也没有改变已有首页像素全等断言。
- 新按钮使首页可见按钮由 2 个增至 3 个；对应测试改为明确核对 `cameraToggle`、`topCameraToggle`、`play`，保留输入数量、交互与暂停断言。
- 截图脚本同时核对新增视角前后的十个观测状态，原地月中心、半径、姿态与模拟状态均未改变。截图等待字体就绪和状态绘制完成，并结束有限 CSS 过渡，避免把过渡中的阶段标签当作最终帧。
- `test-overview-camera.cjs` 仍验证原斜视/平视；完整 observation-audit 与 overview-browser、根 check/test/browser 均通过。

## 性能专项检查

适用项为投影矩阵、总览取景和字体控件布局。沿用当前按需/播放调度与现有球体渲染器，不新增动画时钟、WebGL 上下文、纹理、外部依赖或缓存列表。

本机有窗口 Chrome 157.0.8103.39、1600×900、DPR=1，每个视角播放采样 2 秒：原斜视 rAF p95 13.4ms、最大 13.5ms；垂直视角 p95 13.4ms、最大 13.5ms，均未观测到 long task。原始记录 [overhead-check.json](shadow-review-20261112/overhead-check.json)。rAF 采样不是应用实际绘制 FPS；白板触控、低端 GPU 和长期运行仍未验收。
