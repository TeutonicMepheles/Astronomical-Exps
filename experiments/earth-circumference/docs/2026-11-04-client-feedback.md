## 1. 反馈结论摘要

甲方对首版演示的核心意见是：

1. 不要继续用“地球在轨道附近摆动”表达季节变化。
2. 地球应沿公转轨道移动，自转轴始终保持固定倾斜方向。
3. 太阳光应以固定方向的平行光表现，界面不绘制完整太阳实体。
4. 不要机械地把公转、测量和影子观察拆成三个互不相干的窗口。
5. 面向 5–7 年级学生，不要求使用三角函数计算夹角。
6. 只测量一根立杆；太阳直射点是计算参考位置，不是第二根实测立杆。
7. 观测场景使用无行政边界、无明确地标的抽象实景。
8. 地球纹理和三维视觉应在系列实验中复用，但各实验保留自己的教学重点与配色。

## 2. 公转与太阳光表现

### 甲方直接反馈

- 当前画面中太阳离地球太近，容易误导空间尺度。
- 不需要画出完整太阳实体。
- 地球必须表现公转，而不是在轨道附近来回摆动。
- 地球自转轴应保持固定倾斜方向。
- 太阳和太阳光线保持固定方向，地球在公转轨道上的位置变化导致太阳直射点变化。
- 太阳光应水平、平行射入，并与地球上的直射点位置对应。

### 实现要求

- 使用公转轨道展示地球位置变化。
- 地球经过轨道不同位置时，地轴方向保持一致。
- 不得通过单独旋转地轴或拖动地球摆动来伪造季节变化。
- 直射点位置必须由公转位置、固定地轴和太阳方向共同决定。
- 画面可以不画太阳本体，但平行光方向必须清楚、稳定。
- 若保留太阳边缘，只能作为远景提示，不能让太阳看起来贴近地球。

### 当前实现差距

- 已增加公转概览和固定 `23.44°` 地轴。
- 仍需在整页教学流程中验证公转、直射点和杆影之间的因果关系是否一眼可懂。
- 真实日期太阳位置仍使用教学近似，不是最终高精度星历。

## 3. 多视图与页面布局

### 甲方反馈

- 需要同时说明：
  - 地球公转导致太阳直射点变化；
  - 地面立杆和影子的测量；
  - 地球上的观测点、直射点和同经线关系。
- 不建议做成三个完全割裂、互相没有空间联系的窗口。
- 可以采用融合布局，或者提供简单、明确的视图切换。
- 课堂讲解时应能方便返回完整信息。

### 推荐布局

```text
┌──────────────────────────────────────────────────────┐
│ 当前任务：选点 / 测影 / 测距 / 计算                  │
├───────────────────────────┬──────────────────────────┤
│ 公转与直射点总览          │ 地面立杆、光线和影子     │
│ 固定地轴、太阳平行光      │ 直接显示夹角             │
├───────────────────────────┴──────────────────────────┤
│ 地球定位 / 同经线参考点 / 经线距离                   │
├──────────────────────────────────────────────────────┤
│ 分步计算与地球周长结果                               │
└──────────────────────────────────────────────────────┘
```

该结构是建议，不是已锁定的像素布局。可拆分为视图切换，但应保持同一套颜色编码和连续任务上下文。

### 视觉关系要求

- 同一个观测点在总览地球、地面场景和距离测量中使用一致标识。
- 太阳直射点应使用与观测点不同的颜色或形状，避免混淆。
- 切换视图时保留当前地点、日期和已完成的测量状态。
- 不使用多层悬浮面板长期遮挡主场景。

## 4. 面向 5–7 年级的测量与计算

### 甲方反馈

- 不使用三角函数推动实验流程。
- 不要求学生手动计算阳光与木棍之间的夹角。
- 直接显示阳光、木棍、影子和夹角数值。
- 测量完成后，将角度代入最终公式，求得地球周长。
- 计算步骤应简化，重点是理解测量关系，而不是进行复杂数学推导。

### 实现要求

- 杆影角以可视角度弧、数值和文字共同表达。
- 学生只需要确认或读取角度，不要求输入 `arcsin`、`sin` 等函数。
- 计算公式可以使用：

```text
地球周长 ≈ 360° ÷ 杆影角 × 同经线距离
```

- 公式变量应与地面视图和地球视图中的对应对象联动高亮。
- 计算过程按顺序揭示，先显示已知量，再显示代入过程，最后显示结果。
- 若保留纬度差计算支路，应明确它是核对路径，不能让学生误以为需要进行两套复杂运算。

## 5. 单观测点模型

该模型已于 2026-11-03 明确确认，并与 2026-11-04 的课堂简化方向一致。

- 学生只操作一根实际立杆。
- 观测点由学生选择。
- 太阳直射纬度由日期和太阳位置计算。
- 同经线参考点是计算位置，不是第二个需要插杆测量的实验点。
- 经线距离在观测点与同经线参考点之间测量。
- 计算使用杆影角或纬度差，不要求重复进行第二根立杆实验。

### 当前实现差距

- 第二阶段目前仍要求分别记录观测点影端和太阳直射点影端。
- 这会把参考点误做成第二次实测，需改为单次杆影测量。
- 杆长仍固定为 `100 cm`，正式需求仍要求支持 `10 cm–1 m` 输入。

## 6. 地面场景与地球视觉

### 甲方反馈

- 观测点可能覆盖任意经纬度，无法为每个点准备真实照片。
- 地面场景应采用抽象实景，不依赖具体行政区域或地标。
- 可以使用山地、水面、平地等环境变化区分观测条件。
- 不显示政治边界。
- 地球应使用无行政区块纹理，并保持手绘、科普插画风格。
- 系列实验中的三维地球技术方案应复用。

### 视觉要求

- 地面水平线清楚，立杆与地面垂直。
- 平行光线、影长和夹角是主要视觉证据。
- 地面背景不能抢走杆影的可读性。
- 地球经纬线保持低对比，当前经线和测距弧提高对比。
- 观测点和太阳直射点不能只靠颜色区分。
- 保证 16:9 智慧白板横屏下完整可见，不依赖悬停、滚轮或页面滚动。

## 7. 需要保留的交互

- 选择观测地点。
- 选择日期。
- 输入或选择杆长。
- 在地面视图中测量影子或确认杆影角。
- 在地球视图中查看观测点、同经线参考点和经线距离。
- 沿当前经线测距。
- 分步查看计算公式。
- 得到地球周长结果。
- 修改日期或地点后，旧直射点、参考点和测距结果失效。

## 8. 验收清单

- [ ] 地球沿公转轨道移动，而不是原地摆动。
- [ ] 地轴保持固定倾斜方向。
- [ ] 太阳以固定方向的平行光表示。
- [ ] 不出现完整、近距离的太阳实体。
- [ ] 公转位置变化能够解释太阳直射点变化。
- [ ] 公转、地面测量和地球定位之间有明显空间或状态联系。
- [ ] 不要求 5–7 年级学生使用三角函数。
- [ ] 地面视图直接显示阳光、木棍、影子和夹角。
- [ ] 只有一个实际观测地点和一根实测立杆。
- [ ] 太阳直射点仅作为计算参考点。
- [ ] 经线距离严格沿观测点与参考点的共同经线测量。
- [ ] 地面场景无行政边界和明确地标。
- [ ] 地球无国境线，保持手绘科普风格。
- [ ] 公式变量与图示对象能够对应。
- [ ] 日期或地点改变后旧测量结果被清除。
- [ ] 页面在 16:9 白板中完整显示，不依赖滚动。

## 9. 仍待确认

- 地点选择采用快捷地点、地球点击、经纬度输入，还是组合方式。
- 默认地点、日期范围、坐标精度和日期控件形式。
- 杆长的步长、默认值和测量单位显示方式。
- 经线距离的单位、拖动步长、吸附规则和显示精度。
- 杆影角由学生拖动影子测量，还是由系统根据日期、杆长直接给出。
- 是否保留“观测支路”和“模型支路”双路径核对。
- 公式采用学生输入、逐步填空，还是系统分步揭示。
- 地球周长参考值、允许误差和结果展示精度。
- 多视图采用同页融合、双视图还是三视图切换。

## 10. 不应继续采用的做法

- 不通过拖动地球或旋转地轴来改变季节。
- 不画出贴近地球的完整太阳。
- 不把太阳直射点当作第二个实际观测点。
- 不要求小学生用三角函数计算入射角。
- 不使用真实地图、行政边界或依赖具体地标的背景。
- 不用三个完全割裂的窗口分别讲互不关联的内容。
- 不在主舞台加入长页面滚动或必须悬停才能理解的信息。
