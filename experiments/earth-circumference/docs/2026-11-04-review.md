## Remaining boundaries

Visual demonstration only; not real-date solar calibration. Radius 6371 km is a spherical approximation. Site scenes are illustrative; long shadows are display-clipped, and nonpositive solar altitude reports no ordinary daylight shadow. Real whiteboard touch, long-run performance, scientific workflow completion, and human visual acceptance remain separate. Changes are local and not pushed.

## Central-angle interaction revision

Observation now retains translucent terrain and lighting beneath the grid. A 48-logical-pixel center button has a slow 2.6-second CSS pulse. Clicking it draws two warm-white dash-dot radii from the geographic markers inward over 1.8 seconds; the projected angle arc and numerical value fade in only after the radii reach the center. Repeat clicks are disabled. Returning resets the reveal, and a new selection uses new geometry. The short animation loop stops on completion or exit; the globe's WebGL canvas is not redrawn continuously by this effect.

Both endpoint normals come from the same globe basis as the rendered map. The value is acos(clamped dot product); the angle arc uses spherical interpolation of the normals before orthographic projection. Thus a visually foreshortened angle is not misread as the physical central angle.

Recorded Chrome verification: default central angle 38.627385°; a second real-click selection gave 14.527385°, matching its same-meridian latitude difference within floating-point precision. The angle stayed hidden at the animation midpoint, appeared after convergence, did not move the locked globe, persisted across right-panel site switching, and reset on reentry. Keyboard Enter also triggers it. No page JavaScript errors. Files: angle-before.png, angle-drawing.png, angle-complete.png, angle-flow.webm, delivered separately.

## Return-transition cleanup

The older meridian SVG layer used an HTML-style `.hidden` property without an explicit SVG attribute/style rule, so its path could remain visible during return. It now uses a real hidden attribute and a stage-mode CSS guard. A synchronous mode-change event hides and clears both auxiliary layers at the start of return, cancels the angle animation, and clears the angle text/path rather than waiting for a later globe frame. This also prevents an unfinished callback from restoring the overlay.

Regression covers returning after full reveal, during radius drawing, and rapid entry/exit. Each checks visibility and empty geometry in the same event turn, again during camera retreat, and after animation callbacks would have completed; reentry must restore an unused center button and the current meridian arc.

## Line variants and user shadow measurement

The observation stage now offers Original / Sketch / Draft variants. Sketch uses a stationary, deterministically generated SVG ink pattern clipped by the exact stroke; no displacement, path jitter, or per-frame randomization. Draft uses fine dash-dot centerlines, endpoint crosses, arc ticks, and a rectangular tabular label. The same styles apply to the globe's measurement aids and the user-drawn shadow line. Path strings, endpoint transforms, angle values, and saved measurements are invariant when switching styles.

The right scene remains 672×350 display units with a 660×400 authored image coordinate system. Start measurement, click base and tip, drag either handle (or use arrow keys), then record. Records are separate for selected/subsolar sites. Remeasure clears only the current site; returning to the same scene preserves results, while changed latitude/longitude/season invalidates both records. Nonpositive solar altitude or an off-image shadow endpoint disables this image-based measurement rather than presenting a shortened physical shadow.

Readout is image-coordinate distance computed exclusively from user marks. No metre calibration exists in the project docs; the model shadow ratio is not used as the measured result. Pointer coordinates use the actual displayed SVG rectangle with its explicitly nonuniform viewBox mapping. This avoids assumptions about screen pixels, parent-board scale, and CSS-transformed CTMs. Touch target circles preserve at least 44 screen pixels in each direction.

Verification: actual mouse drag changed 140 to 160; keyboard adjustment changed 160 to 161. Independent subsolar record remained 0. Remeasure left the other site untouched. Touch taps at 1280×720 measured 130 image units; the full panel fit. Same-scene reentry retained it; changing season reset both. Three style screenshots share identical path data and angle values. Root check, unit tests and browser smoke passed; separate EXP-04 recording completed without page errors. Review: review/measurement-review.html.

Performance scope: the ink tile has 800 small vector dabs created once and reused as a pattern. No new animation clock, canvas texture upload, or raster filter was added for style switching. Measurement updates only the small SVG overlay and readouts on input/context updates; physical-whiteboard and long-run performance remain unverified.

## 2026-11-08 orbit-overview revision

The first stage is now split into a left-side revolution overview and a right-side enlarged Earth. The date timeline advances a small Earth around an inclined projected orbit while every corner Earth keeps a parallel, fixed `23.44°` axis. The enlarged Earth is visually connected back to the current orbital position and shares the same Cooper `N+284` date model used for the subsolar latitude.

The previous date-to-axis-tilt inverse solution and drag-to-change-date axis control were removed from the active behavior. For each date, the Earth-to-Sun direction is solved against the fixed axis so `dot(axis, sun) = sin(delta)`; spin is then chosen so the local-noon subsolar point keeps the selected point's longitude. Selecting a different point preserves the date, and changing the date preserves the selected latitude and longitude while recomputing both the orbit position and subsolar point.

Model regression tests cover every day of 2026, checking the previous date formula against the rendered orthographic basis, the fixed axis, visible-hemisphere sunlight, continuous orbit motion, seasonal orbit quadrants, and the `26°` illustrative orbit pitch. Browser recording at 1600×900 and 1280×720 covered date drag/keyboard input, point selection, orbit movement, same-longitude alignment, and transition into the observation stage without page errors or page scrolling. Static check, root unit tests, root browser smoke, and the dedicated orbit test passed. This is implementation evidence, not final whiteboard or scientific acceptance.
