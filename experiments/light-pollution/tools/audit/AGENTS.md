# 光污染性能专项工作约定

遵守[根约定](../../../../AGENTS.md)及[实验约定](../../AGENTS.md)。本文件位于性能诊断工具目录；上级入口要求本实验新增或修改功能、制定及执行跑测时主动阅读，不依赖子目录规则自动覆盖其他模块。功能任务同时遵守所属模块 README。

## 每次功能变更的性能检查

- 实现前判断是否新增或改变动画时钟、事件频率、整景合成、Canvas/WebGL 绘制、纹理上传、图片解码、同步计算、DOM 布局、存储写入、缓存容量或资源生命周期。将适用项纳入方案，不等出现卡顿才分析。
- 跑测前核对功能与已有动画、面板及整页交互叠加后的负载；新增操作或压力状态不在现有脚本覆盖内时，补充对应回归场景。不要仅凭现有脚本通过判断新增功能性能正常。
- 涉及上述运行开销时，按本文件进行相关前后采样及整页交互回归；缓存或资源变更同时检查失效正确性、重复打开/关闭与释放。纯文档等不影响运行的变更可记录不适用理由，不要求机械执行完整性能采样。
- 交付说明或所属验证报告写明“性能专项检查”：适用风险、实际检查及结果、未验证项；无适用项时写明理由。不得把已阅读约定等同于性能验收通过。

## 职责与入口

- 本目录拥有测量、复现和审计工具，不拥有产品运行逻辑。工具用法以[README](README.md)为准。
- 调度与探针由 core 管理，装配由 app 管理，业务与交互由 features 管理，合成与缓存由 rendering 管理，资源加载释放由 resources 管理。修复回到实际责任模块，不把业务代码搬入 audit。
- 先读[架构](../../docs/ARCHITECTURE.md)、[验收记录](../../docs/VALIDATION.md)及[2026-10-29 实测报告](../../docs/CHROME-PERFORMANCE-2026-10-29.md)。历史数据仅帮助定位，不能当作当前版本的结果或硬性性能预算。

## 先测量，再定位

1. 检查分支、未提交改动及服务实际来源。记录提交、改动状态、URL、构建来源；多工作树时核对 HTTP 返回内容与目标 standalone 文件，不能仅凭 HTTP 200 判断版本。
2. 用安装在本机的有窗口 Chrome 复现整页操作。记录 Chrome 版本、视口、DPR、设备及 GPU 信息（可获取时）、前台/焦点、采样时长和压力状态。隔离测试配置，不覆盖用户草稿。
3. GPU 性能采样串行进行，避免并发浏览器测试互相干扰；区分冷启动、加载、稳定运行和交互阶段。比较前后时保持环境、操作序列和画质一致，差异需说明。
4. 同时观察 rAF 间隔及尾帧、长任务、输入响应、合成次数/耗时和内存趋势。需要时保留 CPU profile；不能只测一个滑条或只报告平均帧率。
5. 优先核查重复整景合成、转场纹理上传、缓存失效范围、逐像素几何重算与资源释放。通过调用栈或对照样本确认原因；秒级间隔没有长任务时，不直接断言是主线程、GPU 或窗口遮挡。

## 修改边界

- 重绘通过统一调度入口合并，首次 ready 必须对应已完成的首帧。避免新增独立动画循环或空资源加载回调触发重复合成。
- 缓存键覆盖真正影响输出的状态；无关改动不清空几何和纹理，源图、可见性、遮罩等相关变化必须失效。缓存应有容量及销毁路径；同时考虑历史引用与 GPU 内存。
- 独立面板通过公共业务接口操作。拖动实时预览，一次手势一次历史，取消恢复原状态；不能通过完整编辑器按钮、内部 DOM 或猴子补丁执行功能。
- 不以降低分辨率、删除特效、改变科学参数或削弱断言换取通过。需要改变画质/功能的方案须明确呈现给用户决定。
- 维护源码并通过现有构建生成 standalone，不手改生成文件作为唯一修复。共享组件和其他实验继续受根目录权限边界约束。

## 验证与交付

所有命令从仓库根目录运行。先按根 README 安装项目依赖，并安装本机 Chrome；该脚本使用 `channel=chrome`，仅安装 Playwright Chromium 不满足要求。先启动服务（独立终端；8090 已占用时核对现有服务来源或换端口）：

```sh
python -m http.server 8090 --bind 127.0.0.1
```

构建并运行本机 Chrome 实际交互测试：

```sh
node experiments/light-pollution/lib-static-demo/export.cjs
node experiments/light-pollution/tools/audit/chrome-interactions.cjs chrome-review.json
```

默认访问 8090 的候选 standalone；其他地址用 LIGHT_URL 指定。输出写入实验 docs，使用未占用且以 `.json` 结尾的文件名，其对应 `.cpuprofile` 也不得覆盖基线。脚本截图目前固定写入 `docs/chrome-billboard-panel.png`，不会随结果文件名改变；运行前将需要保留的截图另存为带日期或轮次的证据文件，运行后核对 Git 差异，不覆盖或丢弃用户已有修改。脚本 pass 表示所含功能断言通过，不代表所有性能场景通过。

- 覆盖默认动画、广告转场、整页平移、建筑亮度/色温/窗帘连续拖动和全窗帘压力状态。广告屏必须验证独立面板、无需完整编辑器 DOM、零亮度点选、实时预览、单步撤销/重做、Esc/取消、面板互斥和播放控制。
- 按改动运行核心测试与专项；交付执行 `npm run check`、`npm test`，影响页面时执行 `npm run test:browser` 及 `node experiments/light-pollution/tools/audit/run-tests.cjs`。文档检查运行 `node experiments/light-pollution/tools/audit/check-readmes.cjs`。
- 异步渲染测试等待实际绘制再读像素，保留原有视觉、几何和状态断言；同时验证 candidate、legacy 及离线兼容，不把生成成功视为浏览器通过。
- 报告记录原因、修复、环境、前后数据、原始证据及未归因异常。合成频率不是屏幕 FPS，事件到后续 rAF 不是正式 INP，短时堆快照不能排除长期泄漏，0 长任务不代表无卡顿。
- 分开列出自动化通过、人工试玩、白板触控、真实旧草稿与长期运行的验收状态。未执行的明确标记待验收；不得承诺所有设备绝对流畅。
- README 随工具接口变更更新；实测数值归 docs 报告，本文件只保留稳定工作约定。提交、推送和 PR 沿用当前用户授权及根流程。
