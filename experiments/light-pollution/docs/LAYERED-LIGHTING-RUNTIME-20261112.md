## 路灯、步道灯与墙灯的配光

### 资产与元数据

将每类灯具拆为固定杆身/墙座、五种配准灯头、发光面与局部受光。源图统一2K，固定接点与原像素裁切不等于降低源图分辨率。道路长杆、步道短杆与挂墙座分别制作，不能强行共用同一透视的完整灯具。

建议的领域数据是设计草案，名称需在实现时对齐实际schema：

```text
fixture: id, family(road/path/wall), ownerLayer, groupId
mount: scenePoint, localBasis, emitterAnchor, emitterPolygon
appearance: bodyAsset, headVariantAssets, authoritativeCanvas
lighting: shade, enabled, gain, color, profileId
receivers: groundPlane / facadePlane 的id与局部区域
occluders: sourceVisibility / receiverVisibility
```

墙灯安装点依附建筑立面局部坐标，跟随整栋移动/缩放；区别于悬空场景坐标。窗内发光与外墙受光分开控制，玻璃可反射墙灯，但不能因此把窗内发光误判为已开启。

### 罩型如何改变散射范围与光晕

每个变体同时有外观与配光配置：发光开口、上/侧/下向角分布、截止方向、边缘软度、透射/反射演示增益。按需熄灯仍只是既有手动关闭演示，真实感应/计时需另做状态机，不能隐含声称已实现。

分开计算四项：

1. **灯头亮面**：受观察方向与罩口可见性控制。灯罩遮住发光面后，直接眩光减弱，不一定使地面也等比例变暗。
2. **空气散射**：按局部朝向与软截止裁切光束；无遮挡时更广，有罩时抑制上方/侧方。不能只改整张光晕透明度。
3. **接收面光斑**：在地面或立面UV中按光源方向、距离衰减与范围求值，经投影及遮挡回到图中。墙灯做竖直墙面向下/上下洗墙分布，不画水平椭圆浮在墙上。
4. **光源Bloom/镜头光晕**：跟随可见亮面和强度软起效，与地面光斑分开；不对整张建筑套光晕。

先用可解释的归一化视觉配光，保留接口将来接真实光度数据。没有确认资料时不声称IES、真实lux或某罩型节能比例。切换罩型不能不加说明地把全部被挡能量搬到地面；透射/吸收/反射演示系数应明确，地面增亮不自动等于现实同功率增亮。

当前高架优先修正点是 `panorama-lighting.js`：roadHead光束的固定half宽度与highway池的固定scale要由配光/接收面模型给出，不能仅让 `variant.spill` 进入灯头halo。步道的 `glow/beam` 则从固定groundY裁条升级为各灯的接收区域；open/cap需要分别制作截止效果，不能只沿用相同spill/ground。

## 动态车流与动态车眩光

### 先清场，再运动

新2K预览以原无灯参考作环境，仍带固定车辆；traffic通道也带固定位置车光。接入动态车辆前，须对这些**局部道路**制作无车、无车影、无烘焙车光的2K补片，保留车道线和透视。移除旧traffic固定光层，再加入动态对象，否则会留下“旧车不动、新车移动、眩光还在原地”的三重残影。

车体资源应无强眩光、无长光束、无固定地面光斑；保留普通灯面或另分灯面。记录四向/必要斜向资源、轮胎接地点、双车头灯与尾灯锚点。当前新包主要只有一张横向car-east，不能直接拿它充当中央道路迎面或背面车型。旧全景11辆车也是特定斜向透视，复用前逐方向审核。

### 路径、透视和车距

旧 renderer 固定 `vp={x:2395,y:145}`、2172×543边界、按y单调的 `xAtY`，且入口需从右上到左下。新图是2736×1536，包含中央纵向道路和前景横向道路：这些常量、方向条件、灯位偏移都不能原样复制。

将车流renderer的道路、入口/出口、接地点和相机/透视映射配置化：

- 中央路先做来向/去向分车道，沿同一地面参考线推进，透视缩放围绕轮胎接地点。
- 前景横路是独立道路族；不能用中央路相同的y单调查表约束。一般三次贝塞尔按参数与弧长查表，深度另由地面映射或标注比例求值。
- 复用同车道共用相位、固定间距、不追赶、完整出画再循环的思想；首次加载确定样式，不逐帧随机。新路径曲率过大时切方向素材或限制路线，不任意旋转一张斜视车图假装转弯。
- 每帧只形成一份姿态快照，车体绘制、命中、灯位、地面光照与眩光均使用这份快照。运动时间留在会话，不每帧写草稿或历史。

### 动态光与镜头效果

车灯光分为“发光开口、随车地面光束、镜头眩光”。高/低光束分别配置前照范围、截止和眩光权重；禁止远光保留普通照明、尾灯与车辆运动。

迎面程度、距离、遮挡共同决定强眩光，不是只要靠近屏幕就产生巨大星芒。尾向主要红色弱光，横向车辆按朝向抑制直接前向眩光。双灯相对车辆接地点定位，随同一姿态变换；可保留旧效果中缓存sprite、射线和鬼影，但重设尺度/方向，不复制旧1920×1080镜头中心与width/700比例常量。

车源被建筑、树或其它前景遮住时，要抑制其镜头halo、射线与鬼影。仅靠把车体画在树后并不能保证所有远处鬼影也消失。光源可见性可查询随静态几何失效的遮挡图/多边形；车前路面的受光则使用接收面的遮挡，不能与镜头可见性混为一项。

旧渲染器每车单次抽样样式、每帧平滑脉动是美术效果；可复用固定样式，不能把脉动宣称为真实照明变化。后续应验证同车无随机闪变、循环不跳光、切换远近光不跳车位。

不是把仓库外HTML里独立的WebGL循环和全局变量整体嵌进正式页面。先提供窄port并与 `scene-store`、session、panel manager和scheduler装配。源码入口、manifest、离线构建一起更新；原有用户草稿不覆盖，新资产修订应独立版本并做明确迁移。

缓存与性能重点：

- 静态材质/窗灯不因车流每帧重新解码或上传。灯罩/强度等改变只使本灯局部场及相关接收面失效；缓存键包括配光版本、光源状态、父图层变换、接收面/遮挡版本及源图。
- 不给每盏灯、每辆车、每罩型各建整景2K缓冲。保留2K源资源，在局部包围盒/图集中复用原像素；用实例参数渲染移动光。
- 当前新预览12张整景纹理RGBA基础体积约192.4MiB，CPU解码/GPU纹理各有此量级开销，尚未计其它内存。它是全景小样，不能作为无条件扩展预算。
- 旧scheduler隐藏页面会停帧并重置时差；但有job时会持续tick，traffic paused的早退不等于所有rAF都停止。验收需区分无draw与无tick；若需完全静止应注销/停用不必要任务，并确保其它水体/广告需求仍正常。
- 旧Canvas `screen` 与新线性加光不能直接混用同一套系数。明确颜色空间和最终混合顺序，并采样是否重复曝光。

## 实施顺序和验收

1. **路灯/步道灯小样**：先用一个固定接点做五罩，分别观察灯头、上射、地面与Bloom；修正现高架beam/pool不随罩型改变的问题。
2. **一面住宅墙灯**：验证挂墙锚点、下照或上下洗墙、窗灯独立、屋檐及窗洞遮挡；再扩展至居民建筑组。
3. **一条道路动态车辆**：清除静态车，制作匹配方向的2K车型与双灯锚点，完成近/远光、循环和地面受光；再扩展四车道及横向路族。
4. **整页组合回归**：灯罩、墙灯、车流与广告、水体、天空、编辑/撤销同时运行；依据实际采样优化，不以降分辨率或弱化断言通过。

功能验收至少包含：五罩零强度回暗底、上/侧/下配光变化、灯头接点固定、墙灯不重染底材、受光不越过遮挡；来向/背向/横向车、接地点与透视、无追尾/无缝循环、远近光切换不断车、遮源后镜头眩光消失、暂停/隐藏恢复不跳位、旧草稿与取消/单步历史。

本轮实际执行的是：源码对照、上述旧页隔离回读、skill/包校验器检查，以及仓库要求的文档与静态/单元检查。**未修改现有产品运行代码、未制作新五罩/墙灯资产、未将动态层接入新2K场景**。当前对照不能代替新功能跑测。
