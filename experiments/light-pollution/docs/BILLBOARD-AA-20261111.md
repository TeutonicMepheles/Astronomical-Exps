# 广告牌抗锯齿与暗线修复 · 2026-11-11

> 本文保留整理前的开发和采样记录；当前源码交付、资源筛选和复测状态见 [本轮交付记录](DELIVERY_20261111.md)。

## 原因和修复

高分辨率的原图先缩到 2172×543 场景，在广告牌处只剩约 160 像素宽，再按最近邻抽成 256×256 贴图；屏幕模块又按 640×384 cover，导致二次裁切与重复放大。现从原图逆透视、预乘透明度双线性取样为 640×384，直接进入同尺寸屏幕管线。

GPU 用每像素 3×3 覆盖采样处理斜边，保持原输出尺寸；CPU 回退也覆盖抗锯齿路径。保留视频、转场、扫描光、亮度和反射，没有降低场景分辨率或删除效果。

旧黑底清屏区域与半透明的投影边缘重复合成，且旧角点未覆盖完整内屏，产生横穿两面的暗线。现在广告面保留原底图作为边缘底色，去掉黑色预铺层；两面默认角点校正到内框。只迁移精确匹配的旧默认角点，保留用户调整的角点和父图层布局；历史默认贴图精确别名支持升级，用户替换图片及父图层覆盖保留。原 PNG 文件未改写。

## 性能专项检查

高清数据引入了更大的 PNG 字符串。初版采样中发现 renderP95 增至约 40–47 ms；GPU 改为像素内采样后仍存在同级开销，继续定位到每帧多次 getData 经 JSON 序列化复制图片字符串。现递归复制可变容器，共享不可变字符串；快照分离测试防止编辑数据反向修改内部状态。

环境：有窗口 Chrome 157 / RTX 5080 / 1600×900 / DPR 1，串行采样，中性、三层调色、连续拖动各 4 秒。最终 renderP95 2.9/3.9/8.7 ms，rAF P95 13.4/13.4/13.5 ms，长任务均 0。原始证据：[修改前](billboard-before-performance-20261111.json)、[首版](billboard-after-performance-initial-20261111.json)、[仅 GPU 优化](billboard-after-performance-gpu-only-20261111.json)、[最终](billboard-after-performance-20261111.json)。修改前拖动样本出现 251 ms 间隔，未单独归因，不声称本次修复解决了它。

短采样不能代替物理白板、低端设备和长期运行验收。临时原图读回缓冲在加载完成时释放引用；运行投影输出按对象 ID 复用，销毁时清理，不按帧增长。

最终检查：根 npm run check（0 errors）、npm test、npm run test:browser 和离线导出通过。最终对象快照复制实现已通过独立容器变更隔离、对象、建筑和纸质面板专项。纸质面板专项复测曾因被绑定车辆驶出画面后才执行折叠气泡点击而超时；其稳定性场景现固定车速 0，保留原暂停按钮、快速开关、取消、离线和持久化断言，实际行驶与悬停跟随由独立车流和气泡专项验证。

同环境修改前 renderP95 为 6.4/7.1/9.8 ms，最终为 2.9/3.9/8.7 ms；记录只代表上述短时采样。未提交或推送。
