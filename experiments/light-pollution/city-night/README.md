## 使用方法

从仓库根运行 npm run dev -- --experiment light-pollution，使用终端实际地址。离线导出运行 npm run export -- light-pollution。整页专项运行 node experiments/light-pollution/city-night/verify.cjs，CITY_URL 必须指向当前工作树的 city-night/index.html；GPU 检查串行执行。

## 公开接口与数据

lightingUI 提供选择、特写和关闭接口；scenePreview 提供只读状态、相机、像素、固定时间车流及统计。住宅与上方相邻楼合并为一个“居民住宅”入口，窗灯同步，墙灯单独调节。仅居民住宅提供“查看局部”，其他对象仅在全景调节。全景面板避让两栋建筑。

## 依赖与解耦策略

右上显示波特尔等级（演示）和当前画面实绘星点数。sky-model.js 归一化十类光源的当前亮度/灯罩/时段/远近光，经明确的教学权重合成0—1污染量，映射1—9演示等级及星点可见阈值。不是观测星表、真实星等、SQM或经标定的波特尔预测。远景窗灯仅2.5%权重，路灯/体育场/商业屏等为主要贡献；冷暖、月光、天气、暗适应未建模。

6000个固定种子星点只在天空遮罩内生成，位置、明暗层次固定，不闪烁；降低污染平滑放开阈值，显示本视口超过可见阈值且实际绘制的点数，不套用波特尔星数表。特写不含天空时实绘星数为0。原底图不改，独立sky-clean.png只清理天空烘焙星点并保留材质；山体和城市不覆盖。新增静态VBO144000字节、一张2736×1536 RGBA纹理16809984解码字节，仍同一调度和静态缓存；pagehide释放。

### 开发者气泡定位

默认气泡移至对应对象稍靠上位置。长按Ctrl约3秒打开开发者模式，点「拖动气泡位置」后，调光面板收起，气泡显示虚线外圈，可用鼠标或Pointer Events触控拖动；顶部工具条点「保存位置」写入当前浏览器本机存储。点「退出定位」或Esc返回普通点击调光。退出不自动保存，未保存的位置仍保留在当前页面，刷新恢复最近一次保存值。

坐标按16:9画面的百分比记录，窗口缩放保持相对位置；不会修改光源、星空、模型读数、完成状态或源码默认值。开发者面板另有「恢复默认位置」（需再次保存才跨刷新生效）和「导出气泡位置」JSON，可用于留存或后续同步源码/其他设备。保存范围为当前浏览器及页面来源；不自动跨设备、浏览器或HTTP/file来源同步。本机存储不可用时显示失败状态，仍可导出。

标记布局由lightingUI.markerLayout公开接口管理；localStorage键city-night-marker-positions-v1。仅接收已知对象、有限数值及舞台内坐标，损坏数据回退默认。拖动使用Pointer Capture，取消、失焦、失去捕获、窗口尺寸变化时回退本次未完成拖动；不逐像素写存储，不新增动画循环或GL资源。

场景10个气泡与对应面板标题统一使用runtime.js中的面性SVG图标家族（filledIcons），32×32画布、currentColor填色与留白，不使用stroke或线性图标；气泡颜色、选中状态及点击名称保持。灯罩按钮继续使用原灯罩图片，关闭等操作按钮沿用原UI资源。
