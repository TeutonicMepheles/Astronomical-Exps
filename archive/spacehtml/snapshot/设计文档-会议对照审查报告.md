## 一、会议核心共识（设计必须遵循的原则）

会议中反复确认了以下几条**不可偏离**的顶层设计约束：

| # | 原则 | 会议原文依据 |
|---|------|------------|
| P1 | **定性优先于定量** | 张瑶："我们这个实验不是仿真模拟……可能就用一组相对理想化的定性抽象实验去代替" |
| P2 | **离散有限选项，非连续变量** | 张瑶："每个参数3–5种……不会太多"；柳喆俊："预先做好的有限的选择为主" |
| P3 | **不依赖外部 API / 数据库** | 柳喆俊："肯定不能依赖第三方的……他那边的网断了就用不了了" |
| P4 | **学生手动测量+纸笔计算，非自动出答案** | 张瑶："学生是用三角形公式在纸笔上算……可以一键点击看答案来对" |
| P5 | **轻量静态网页，单屏无滚动** | 张瑶："教室电视上没有办法上下滚动……所有信息在一屏上显示"；"不超过100兆" |
| P6 | **视觉风格：简洁不幼稚** | 张瑶："不希望做得太低幼……尽量简洁一点，不用太花哨" |
| P7 | **学生=实验者角色** | 张瑶："一定要让学生去输入实验条件……观察实验结果并记录下来……做10次实验得到10组数据然后分析" |
| P8 | **公式由天文馆方提供，不需自行推导** | 张瑶："公式我们会给的" |

## 二、逐实验对照分析

### 实验一：傅科摆模拟实验

| 会议要求 | 设计文档现状 | 偏差判断 | 严重程度 |
|---------|------------|---------|---------|
| 地理位置选择：**有限点（约10个）**，沿纬度分布 | 5个预设+自定义滑块（0°–90°连续） | ⚠️ 偏差：自定义连续纬度超出范围。应改为10个左右离散城市点 | 🟡 中 |
| 摆长和摆锤质量作为**输入参数** | 连续滑块（5–70m, 5–50kg） | ⚠️ 偏差：应改为有限档位（如3档摆长×3档质量） | 🟡 中 |
| 核心输出：**偏转周期**（如"上海：46h35m偏转一圈"） | 偏转角速度+偏转周期+摆动周期全部实时显示 | ✅ 核心数据正确，但信息量偏多 | 🟢 低 |
| 动画效果：摆锤摆动+偏转，带**加速** | 时间加速倍率（1×/60×/3600×） | ✅ 正确 | 🟢 — |
| 地面效果："有一点弧度的地面" | 侧视图+俯视图双视角，地面刻度盘 | ✅ 正确（可加强弧形地面表现） | 🟢 — |
| 赵茁栋确认："如果只是单摆模拟+旋转速度，就比较好实现" | 完整阻尼物理模型 | ⚠️ 过度工程化。应简化为纯运动学近似：纬度→偏转周期→旋转角速度，直接驱动动画 | 🟡 中 |
| 小学阶段：**不教公式，只展示结果** | 区分了5-6年级和7-9年级目标 | ✅ 正确 | 🟢 — |
| "对比模式"和"我的预测模式" | 有设计 | ⚠️ 会议未讨论，属于自行扩展。保留可，但非必需 | 🟢 低 |

**实验一小结**：核心方向正确，但**参数应离散化**（有限城市+有限摆长档位），物理模型应简化为**运动学近似**而非完整动力学模拟。

### 实验二：月面环形山高度测量实验

| 会议要求 | 设计文档现状 | 偏差判断 | 严重程度 |
|---------|------------|---------|---------|
| 核心交互：学生**拖拽标尺测量影长**，类似百度地图测距 | 有"手动测量模式"支持拖拽 | ✅ 正确 | 🟢 — |
| 高度计算：学生**纸笔手算** `h = s × tan(α)` | **自动显示计算结果**（"计算高度 h: 3.20 km"） | 🔴 **严重偏差**：结果面板直接显示答案，剥夺了学生手动计算的核心教学环节 | 🔴 高 |
| 答案展示：**隐藏的"查看答案"按钮**，学生算完再对 | 答案直接显示在界面上 | 🔴 **严重偏差**：应改为默认隐藏，点击后才显示 | 🔴 高 |
| 太阳角度：**滑块调节**（明确否定了数据库方案） | 弧形滑块+快捷按钮 | ✅ 正确。柳喆俊明确说"不需要数据库" | 🟢 — |
| 影子来源：**3D模型动态生成**，非真实照片 | Canvas剖面图+射线追踪阴影 | ✅ 方向正确（但可进一步简化为纯几何阴影，无需射线追踪） | 🟢 — |
| 环形山模型："可以简化，像一根杆子"，甚至只需要抽象的山形 | 5个预设环形山（哥白尼、第谷等）+高斯函数轮廓 | ⚠️ 偏差：预设过多，且命名真实环形山可能误导学生认为数据也真实。建议简化为1–2个抽象环形山模型 | 🟡 中 |
| 精度评分：会议**未提及** | ⭐⭐⭐精度评分系统 | ⚠️ 会议没有这个需求。张瑶明确说"不可能很精确……只能测个大概" | 🟡 中 |
| 测量点：**不应限制**（柳喆俊："不用固定几个点"） | 手动测量模式不限制点 | ✅ 正确 | 🟢 — |
| 多角度验证：同一环形山换不同太阳角度多次测量 | 有太阳角度调节 | ⚠️ 未显式设计"同一环形山多次测量对比"功能 | 🟢 低 |

**实验二小结**：**最关键的偏差是答案自动显示**。必须改为：默认隐藏计算结果，学生手动拖拽测量影长→纸笔计算高度→点击"查看答案"按钮验证。

### 实验三：陨石坑撞击模拟实验

| 会议要求 | 设计文档现状 | 偏差判断 | 严重程度 |
|---------|------------|---------|---------|
| 参数：**离散选项**（每参数3–5种） | **连续滑块**（1–1000t, 1–30km/s, 0–90°） | 🔴 **严重偏差**：会议反复强调"3×3×3=27种组合"，明确否定连续变量 | 🔴 高 |
| 结果：**有限的预设坑类型**（约10–27种） | 施密特标度律公式**实时计算**坑尺寸 | 🔴 **严重偏差**：不应实时计算物理量，应展示预设的坑图像/模型 | 🔴 高 |
| 坑展示：**3D模型，略倾斜视角，有月面地平线弧度** | 2D剖面图+粒子动画 | ⚠️ 偏差：应增加3D倾斜视角静态展示 | 🟡 中 |
| 定性 vs 定量：**偏定性演示** | 显示精确数值（坑直径12.3km、深度2.1km、能量5.0×10¹⁶J） | ⚠️ 偏差：定量数据展示过度。张瑶说"定量的成分更少一点，是定性" | 🟡 中 |
| 学生角色：**上台点击发射**，记录结果在纸上 | 有发射按钮，但无纸笔记录引导 | ⚠️ 缺少"记录表"引导UI | 🟡 中 |
| 动画阶段：撞击瞬间动画 | 4阶段动画（接近→接触→扩展→稳定） | ✅ 方向正确 | 🟢 — |
| 粒子数量 | 500粒子爆炸系统 | ⚠️ 可能过重，会议未要求粒子数量 | 🟢 低 |
| 预设场景（恐龙灭绝级等） | 5个预设 | ⚠️ 恐龙灭绝级（100000t）超出月球陨石坑的教学范围 | 🟡 中 |
| "对比实验模式" | 并列运行两次撞击 | ⚠️ 会议未讨论，自行扩展 | 🟢 低 |
| 能量换算TNT当量 | 有设计 | ⚠️ 过度定量化 | 🟡 中 |

**实验三小结**：**最大偏差是把一个"离散选项→预设结果"的定性演示做成了"连续参数→物理模拟"的定量仿真**。需要回退到：3–5档质量 × 3–5档速度 × 3–5档角度 → 预渲染的坑类型图像/3D模型。

## 三、跨实验的系统性偏差

### 偏差1：参数类型 — 连续化过度 🔴

**现象**：设计文档大量使用连续滑块（range input），但会议反复强调**离散有限选项**。

| 实验 | 设计文档（连续） | 会议要求（离散） |
|------|---------------|---------------|
| 傅科摆 | 摆长5–70m连续、质量5–50kg连续 | 有限档位 |
| 环形山高度 | 太阳角1°–89°连续 | 连续滑块可接受（角度是核心变量） |
| 陨石撞击 | 质量/速度/角度全连续 | **3–5档 × 3–5档 × 3–5档** |
| 日月食 | 任意拖动月球位置 | **预设事件** |
| 地球周长 | 任意自定义城市纬度 | **有限城市点** |

**修正方向**：将大部分滑块改为卡片式选项按钮组（3–5个选项），仅在核心教学变量（如太阳高度角）保留滑块。

---

### 偏差2：答案呈现方式 — 自动显示过度 🔴

**现象**：设计文档中多个实验直接自动显示计算结果，违背了"学生手动计算"的核心教学理念。

**会议原文**（张瑶）：
> "学生是用三角形公式在纸笔上算……可以一键点击看答案来对……不是直接显示在画面上"

这决定了**所有定量实验**的数据面板设计逻辑：

```
❌ 错误设计：┌─────────────────┐
            │ 影长: 3.20 km   │  ← 自动显示
            │ 高度: 3.20 km   │  ← 自动计算
            └─────────────────┘

✅ 正确设计：┌─────────────────┐
            │ 你的测量: ___ km │  ← 学生拖拽后显示影长
            │                 │
            │ [🔍 查看答案]    │  ← 点击才显示高度
            └─────────────────┘
```

**影响实验**：实验二（环形山高度）、实验五（地球周长）

---

### 偏差3：物理模拟深度 — 过度工程化 🟡

**现象**：设计文档对多个实验设计了完整的物理仿真模型，但会议倾向于**简化的运动学/几何近似**。

| 实验 | 设计文档 | 会议倾向 | 偏差 |
|------|---------|---------|------|
| 傅科摆 | 阻尼+完整动力学 ODE | 单摆+固定旋转速度（赵茁栋确认可行） | 过度 |
| 陨石撞击 | 施密特标度律+缩放公式 | 预设坑类型匹配（离散参数→离散结果） | 过度 |
| 日月食 | 实时阴影锥几何计算 | 预设事件+时间轴插值动画 | 过度 |
| 火箭发射 | 空气阻力+重力衰减+齐氏方程 | 未知（需对齐王磊demo） | 待确认 |

**会议原文**（柳喆俊）：
> "要弄得很准确非常非常难的……航天所里的专家合公式都合不清楚……如果是一次过程的展示，预先准备好的数据可能会好一点"

**修正方向**：
- 有公式的 → 直接用公式计算（不模拟中间物理过程）
- 没公式的 → 用预设数据插值
- 核心原则：**展示结果，不仿真过程**

---

### 偏差4：学生角色定位 — 被动观察多于主动实验 🟡

**现象**：部分实验设计偏向"可交互的科普动画"，偏离了"模拟实验"的核心定位。

**会议原文**（张瑶）：
> "我们这个天文实验课有个套路……一定要让学生去输入一个实验条件……点击开始实验……观察实验结果并记录下来……做10次实验得到10组数据然后分析"

这意味着每个实验的UI应该有清晰的**实验流程引导**：

```
明确需要的流程元素（当前设计缺失）：
1. 实验条件设置区（输入）
2. "开始实验"按钮（触发）
3. 实验过程观察区（动画）
4. 实验结果记录提示（输出引导）
5. 多次实验数据对比（可选）
```

当前设计文档偏重"展示效果"和"交互控件"，但缺少**实验流程引导UI**。

---

### 偏差5：视觉风格 — 缺少"简洁不幼稚"的具体锚点 🟡

**会议原文**（张瑶）：
> "不希望做得太低幼……尽量简洁一点……不是那种很儿童版的卡通效果"

当前设计文档给出了配色方案和UI规范，但未提供**视觉参考锚点**（mood board方向）。张瑶提到希望同济团队提供视觉风格参考，因此设计文档中可标注"视觉风格待定，由开发方提供参考方案后确认"。

---

### 偏差6：部署约束 — 部分设计可能过重 🟡

| 约束 | 会议要求 | 当前设计风险点 |
|------|---------|-------------|
| 文件大小 | <100MB | 陨石撞击3D模型、星空2000+粒子可能累积过大 |
| 单屏无滚动 | 教室电视16:9一屏 | 部分实验布局（控制面板+画布+数据面板+知识卡片+底部引导条）信息密度过高 |
| 无外部依赖 | 纯静态 | ✅ 当前设计正确 |
| 性能 | 教室网络+设备有限 | 粒子系统（2000星点+500撞击粒子）需验证在低配设备上的帧率 |
